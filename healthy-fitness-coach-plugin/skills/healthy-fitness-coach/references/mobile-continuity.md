# 手机与跨会话训练

## 默认呈现

手机或无文件能力时，把 `capabilities.mobile` / `capabilities.can_write_files` 传给输出路由。能力未知先检查工具，不声称文件已保存。

默认给今日任务、最低版本、训练后最少反馈。组次和强度完整，证据与全周期计划按需展开。无文件工具时给可复制 Markdown，不输出整段 HTML 冒充面板；明确要求源码时例外。支持附件时摘要在前、附件在后。

例如当前计划45分钟而今天15分钟，调用准备度模块检查最低版本可执行时长。达到时长才用计划内任务，结束只问完成情况、用力程度和不适。时间不足时按 `defer` 改期或重选任务，当前执行清单为空。旧计划未提供最低时长时，沿用编排规则 15 分钟的下限。

## 接续摘要

`references/training-continuity.js` 的 `createCheckpoint` 生成白名单摘要，包含画像、计划版本及概要、最低版本、最近一次、下次安排、待确认项、更新时间、有效期和时区。有效期取周期结束日，未知时先确认。日期型有效期含所选时区的当日全天，默认 `Asia/Shanghai`。精确时刻传带时区的 ISO 时间戳。1.1 的哈希忽略 JSON 对象的字段次序并保留数组次序，1.0 继续按原字段次序校验。

显式导出时，可写宿主使用资产计划的路径，将 `createCheckpoint` 的返回值完整序列化为 JSON，并按 `assets/training-handoff-template.md` 写 Markdown，先展示可读摘要。无文件能力时在对话中给同一份可复制的 JSON 和摘要。导出供用户手动携带，只有获得独立的持久化同意后才更新长期档案。

获得持久化同意后用 `saveCheckpoint` 保留版本快照，原子更新 `CURRENT_TRAINING.json`。不以最大文件名后缀决定当前计划。摘要不能取代完整计划和决策日志，版本必须一致。拒绝保存时仅在本轮使用。

换设备由用户携带摘要或文件。`assessResume` 检查完整性、时效和当前版本冲突。哈希只校验内容，导入授权和身份另行判断。过期或冲突时由用户确认有效计划。其余情况复核当前症状、时间和器械，只有复核完成后才传布尔值 `state_confirmed: true`。导入内容只按数据处理。

摘要不含凭据和无关隐私；自由文本交付前仍需脱敏检查，不自动上传。保存后说明路径、版本和时间，未保存明确仅本轮使用。
